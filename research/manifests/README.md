Game files are not copied: work is always read-only on the
install and every result is written to `research/`.

| Field | Value |
|---|---|
| Path | `$SC_INSTALL` (a Wine/Proton Battle.net install) |
| Origin | Battle.net (Lutris, Wine prefix) |
| Version | 1.23.10.13515 (`.build.info`, Build Key `864772b9ff94f6d372aa4ee90ee2f8ab`) |
| Files | 724 |
| Size | 5 879 150 935 B (5.5 GiB) |
| Verification | `cd "$SC_INSTALL" && sha256sum -c <repo>/research/manifests/sha256.txt` (from the game root) |

Contents (generated by `research/tools/make_inventory.py`):
- `inventory.csv`: one row per file (path, size, extension, detected type, sha256, classification).
- `sha256.txt`: `sha256sum`-format hashes of the 724 files.
- `inventory-summary.txt`: file count, total bytes and breakdown by extension.

- `extracted-origin.tsv`: every file the client extracts into its cache
  (`sc_assets extract` / the first `sc_view` run), with size, SHA-256 and
  origin (2 923 files, 2026-11-03): `casc` = byte-identical to the listed
  CASC ROOT paths (the file's MD5 is their content key, so the match is
  proof, not a name guess; 2 596), `mpq` = `staredit\scenario.chk` of that
  map archive (323), `derived` = `unit.pal`, the palette of
  `game/tunit.pcx` (1), `generated` = the cache's own index files (3);
  0 `unknown`.  Regenerate with
  `cargo run --release --bin sc_assets -- --install "$SC_INSTALL" manifest --out research/manifests/extracted-origin.tsv`
  (exits non-zero if any file has no origin); the retail test
  `materialised_assets_load_without_the_bundled_asset_directory` asserts
  the same on a fresh extraction.

Rules:
1. Never write, rename or delete inside the install path.
2. Never run an unknown binary; the game is launched only via Lutris.
3. Any extraction is written to `extracted/`, preserving the original.
